# Phase 1: Project setup

## Done

- A Laravel 13 app (13.38) in the repository root, with Tailwind 4 from the skeleton.
- Livewire 4.
- Pest 5 for tests, with the Laravel plugin. PHPUnit is no longer a direct dependency.
- Larastan 3, configured in `phpstan.neon`.
- The `dfr` script in the project root, with tests in `tests/Feature/DfrScriptTest.php`.

## Decisions

- **Command names**: each dfr command is an artisan command with the `dfr:` prefix. Laravel already has a `list` command, so `dfr list` cannot be `php artisan list`.
- **Mapping in `dfr`**:
  - `init`, `list` and `search` map directly, for example `dfr list` runs `dfr:list`.
  - All other commands take the ID first: `dfr $ID write plan.md` runs `dfr:write $ID plan.md`.
  - With no arguments or `--help`, the script runs `php artisan list dfr`.
  - A first argument that starts with `-` goes to artisan as it is.
- **Current folder**: the script does not change the folder, because `git:add` reads the git repository in the current folder. `artisan` finds the app from its own path.
- **Symlinks**: the script finds the project root with `realpath`, so a symlink to `dfr` in a `PATH` folder works.
- **Alpine.js**: Livewire 4 includes Alpine.js, so there is no separate package.
- **Larastan level**: `max`. The project has no code yet, so the strict level costs little now.
- **Example tests**: removed. The `Unit` test suite is removed from `phpunit.xml` until there is a unit test.
- **Skeleton files**: the `README.md`, `CLAUDE.md` and `AGENTS.md` of the skeleton are not used.

## Open

- `dfr` with no arguments fails with "There are no commands defined in the dfr namespace". The list of commands shows after phase 2 adds the first command. The script itself runs from any folder: `dfr --version` works from `~`.
- Commands with two words, such as `dfr $ID todo add`, map to `dfr:todo` with `add` as the first argument. Phase 3 decides if this is correct, or if they map to `dfr:todo:add`.
