# Add projects by hand

## Done

- `dfr $ID project:add [PATH]` adds the git repository of a folder to the projects of the thing. Without a path it uses the current folder.
- `dfr $ID project:remove [PATH]` removes a project that `project:add` added.
- `.thing.json` has a `projects` list. `ThingProjects` shows the repository of `init` first, then the added projects, then the repositories of the commits.
- The README and the dfr skill tell about the new commands.
- Tests are in `domain/Dfr/tests/Feature/ProjectCommandTest.php`.

## Decisions

- `project:add` stores the top folder of the git repository. A project is a git repository everywhere else in dfr, so a plain folder would break that rule.
- A thing needs this command for work that only reads a repository. That work makes no commit, so `git:add` cannot connect the repository.
- `project:remove` removes only added projects. The repository of `init` and the repositories of commits have their own commands, or none.

## Open

- `project:remove` cannot remove the repository where `init` ran.
