- `~/.claude/skills/dfr` links to `skills/dfr`. `~/.local/bin/dfr` links to the `dfr` script, so `dfr` runs from any folder.
- The Skills section of the README shows the link command.
- The check: thing `mpg` (phase 6, the Web UI) ran over two sessions. Session 2 got only the ID. It ran `read:all` first, added its own todo items, and continued the work without help. Thing `772` (remove the status) used the skill in one session.

## Decisions

- **One skill**: the start, the files and the work steps belong to one flow. Two skills would split the flow, and an agent could load only half of it.
- **New thing by default**: a session usually starts new work. With an ID, the skill continues that thing. The skill uses `list` and `search` only when the user asks, so a session does not pick up the wrong thing.
- **Three standard files**: `plan.md`, `todo.md` and `progress.md`. A fixed set lets each session know where to look. The agent adds other files when the work needs them.
- **`progress.md` only gets `write:append`**: the history of each session stays.
- **Write as you go**: a session can stop at the session limit at any time. Context that is written only at the end gets lost.
- **The ID in each command**: shell variables do not stay between Bash calls in Claude Code, so `$ID` from one call is empty in the next.
- **Append again after the last step**: in `772`, the session appended to `progress.md` and then made a commit. So `progress.md` said "not committed", but the log showed `git:add` after it.
- **Links, not copies**: the copy in this repository stays the only source. A change to the skill reaches each session at once.
