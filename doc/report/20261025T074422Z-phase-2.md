# Phase 2: Core CLI

## Done

- The commands `init`, `list`, `read`, `read:all`, `write`, `write:append`, `write:prepend`, `fm` and `fm:add`.
- The Dfr domain in `domain/Dfr/`, with its source in `src/` and its tests in `tests/`.
- Tests for each command. They run the real `dfr` script with a temporary home folder.
- `symfony/yaml` for the frontmatter.

## Decisions

- **Domain folders**: `domain/Dfr/src/` has `Actions/`, `Commands/`, `Data/`, `ValueObjects/` and `Providers/`. The namespace is `Domain\Dfr\`. The app knows the domain only through its line in `bootstrap/providers.php`.
- **Domain tests**: in `domain/Dfr/tests/`, in their own `Dfr` test suite. Then the domain and its tests can be removed together.
- **Larastan**: checks `app` and `domain/Dfr/src`. It does not check the Pest tests, because it does not understand `$this` in Pest closures.
- **Tests run the real script**: each test runs `dfr` as a process with `HOME` set to a temporary folder. This tests the script, the config file and the piped input too, and never touches `~/.dfr`.
- **Lock**: each write locks `.lock` in the folder of the thing, reads `.thing.json` again, and then writes. A test runs 10 writes at the same time and keeps all 10 files.
- **Atomic writes**: a file is written to a temporary file and renamed. The temporary name starts with `.`, so it is never seen as a context file.
- **ID check**: an ID must contain only lowercase letters and digits, because it becomes part of a path.
- **Filename check**: a filename must not contain `/` or `\`, or start with `.`.
- **Arguments as content**: the arguments become one line, with a space between each, like `echo`.
- **Prepend**: `write:prepend` puts the content after the frontmatter. Before the frontmatter, the frontmatter would stop being frontmatter.
- **`fm` keeps the given YAML as it is**, so comments stay. `fm:add` parses and writes the YAML again, so comments in the old frontmatter are lost.
- **`fm` on a missing file** makes the file, the same way as `write`.
- **`read:all` format**: each file starts with `==> name <==`, the same header as `head` and `tail` use.
- **Output**: file content goes out raw, so text like `<info>` is not changed. Errors go to stderr, so `ID="$(dfr init x)"` never gets an error message.
- **Status**: not in `Thing` yet. It comes with the `status` command in phase 4.

## Open

- `ReadInput` reads stdin when it is not a terminal. A pipe that stays open without data makes the command wait. Claude Code gives `/dev/null`, so it does not wait there.
- `fm:add` loses comments and formatting in the old frontmatter.
- The command classes repeat the checks for the ID and the filename. If phase 3 and 4 repeat them more, move them to one class.
