# Phase 4: Rest of the CLI

## Done

- The commands `status`, `list --status`, `parent`, `parent:remove`, `init --parent`, `list --tree`, `rename`, `search`, `log`, `git:add`, `git:remove`, `files`, `files:reorder` and `files:archive`.
- The `--json` flag on `list`, `search`, `read`, `read:all` and `log`.
- `.thing.json` has the new fields `status`, `parent` and `commits`. `ReadThing` accepts files without them.
- `RunOnThing`: each command on a thing calls it. It checks the ID, runs the work of the command and writes the log line.
- `ChangeThing`: changes the data of a thing while the thing is locked.
- The `dfr` script sets `PAO_DISABLE=1`.
- A feature test file for each new command. One test runs each command on a thing and checks that it writes a log line.
- The README describes the output formats and the new rules.

## Decisions

- **Log in `RunOnThing`**: Laravel sends the command events only outside unit tests, so a listener on `CommandFinished` writes no log in the tests. `RunOnThing` is a plain call that each command makes. It also removes the ID check that each command repeated, which was open since phase 2.
- **Log content**: the time in UTC, the session, the command, the arguments after the ID, the options that were given and the exit code. Failed commands are in the log too, so a session sees what it tried. `init` has no thing before it runs, so it is not in the log.
- **`PAO_DISABLE=1` in the `dfr` script**: `laravel/pao` removes tabs and blank lines from artisan output when an agent runs it. The output of `dfr` is file content and columns, so it must stay exact. Pao stays on for the other artisan commands and for Pest and Larastan.
- **Circle check**: `parent` walks up from the new parent. When it reaches the thing, the command fails. The walk stops at a thing it saw before, so data that already has a circle cannot make it loop.
- **Tree**: a thing whose parent is missing goes to the top. Things in a circle also go to the top, so `list --tree` never hides a thing.
- **`--tree` with `--status` or `--json` fails**: a filtered list loses the parents of the things. The JSON has the parent of each thing, so a reader can make the tree from it.
- **List format**: ID, name and status with a tab between them, also when the status is empty. The columns stay the same for `cut` and `awk`.
- **Status**: free text. An empty text removes it. A new thing has no status.
- **Search**: case is ignored, the text is found as it is (no pattern), and no match exits with 0. Archived files and dot files are not searched.
- **Git**: `git:add` takes anything that git can find as a commit, like a short hash or `HEAD`. It stores the full hash, so `git:remove` can match the start of it. `git:remove` needs 4 or more hex characters, so a short text cannot remove a commit by mistake. The same commit from two repositories is removed together. Git sits behind the `FindGitCommit` interface, because it is an outside system.
- **Reorder and archive check all names first**: when one name does not match a file exactly, the command fails and changes nothing.
- **JSON of a file**: the frontmatter as raw YAML and the body apart. Raw YAML cannot fail to parse and loses nothing.

## Open

- The lock is on one thing. Two sessions that make A the parent of B and B the parent of A at the same moment can make a circle. `list --tree` still shows both things.
- No test covers `PAO_DISABLE`. Pao turns itself off when `APP_ENV=testing`, so the tests cannot see the bug.
- In the text output of `log`, an argument with a line break breaks the line. `log --json` shows it exactly.
- When the work of a command throws an exception, `RunOnThing` writes no log line.
