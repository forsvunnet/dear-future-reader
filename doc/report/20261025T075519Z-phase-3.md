# Phase 3: Todo commands

## Done

- The commands `todo add`, `todo add:after`, `todo add:before`, `todo tick`, `todo untick` and `todo next`, with the `--list` flag.
- The `dfr` script sends `dfr $ID todo add` to the artisan command `dfr:todo:add`.
- `LockThing` and `AddToOrder`, split out of `ChangeFile`, so the todo commands use the same lock and the same file order.
- A unit test for the parser and a feature test file for each command. The tests cover each command with and without `--list`, and each case where a command fails.
- The README describes the rules below, and its examples now work in order.

## Decisions

- **Match rule**: an argument matches an item that contains it, with case ignored. An item that is equal to the argument wins over items that only contain it. This is predictable and still lets a session use short arguments.
- **List title**: the nearest line above the first item that is not blank, without `#` marks and a `:` at the end. `--list` uses the same match rule as the items, so there is one rule to learn.
- **List end**: blank lines between items are part of the list. The first other line ends the list. Lines in the frontmatter and in ``` or ~~~ code blocks are never items.
- **New list**: when no list matches `--list`, `add` adds a `## NAME` list to the end of `todo.md`. Then a session does not have to write a list by hand before the first `add`.
- **Marker of new items**: a new item gets the indent and bullet of the item next to it. A new list uses `- `.
- **One lock for the whole command**: the command reads the lists, checks all arguments and writes the files while the thing is locked. When one argument fails, no file is written. `tick` without `--list` can change more than one file in one command.
- **`next` with all items ticked**: it shows nothing on stdout, writes a note to stderr and exits with 0. An empty result is not an error.
- **Errors**: each argument that fails gets its own line on stderr, so a session sees all problems at once.

## Open

- New lines end with `\n` only. A file with `\r\n` line ends gets mixed line ends after `add`.
- An indented text line under an item, like a second line of the item, ends the list.
- Numbered items like `1. [ ] one` are not todo items.
- The command classes still repeat the check for the ID. The todo commands add six more copies. The message is one line, so a shared class saves little.
