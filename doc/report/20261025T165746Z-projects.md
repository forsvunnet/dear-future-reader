# Projects of a thing

## Done

- `init` stores the git repository of the current folder in the new field `repository` in `.thing.json`.
- The new `ThingProjects` action gives the projects of a thing: the `init` repository and the repository of each commit, each one once.
- `list` shows the projects as a third column, with folder names. `list --json` has `projects` with full paths.
- `read:all` starts with a `Projects:` line when the thing has projects.
- The Web UI shows the projects in the sidebar and on the page of a thing.
- The git test helpers moved to `DfrTestCase`, so all test files can use them.

## Decisions

- A project is a git repository. The commits already store their repository, so only the `init` repository is new data.
- The new contract `FindGitRepository` stands in front of git. `FindGitCommitWithGit` uses it to find the top folder.
- `list` shows folder names to keep the line short. `--json` has the full paths.
- `read:all --json` stays a list of files, so its shape does not change.

## Open

- A git worktree has its own top folder, so it shows as a separate project.
- Two repositories with the same folder name look the same in `list` and the sidebar.
- Things made before this change have no `repository`. They show only the repositories of their commits.
