# Phase 0: Decisions

## Done

- Wrote the decisions in [doc/decisions.md](../decisions.md).
- The README now names the location of the things and the config file.
- The README no longer says that `write` warns about missing frontmatter.
- The README now says that `log` shows each command, not only the changes.

## Decisions

- **Location**: `~/.dfr/<ID>/`. Data outside the app folder stays safe when the app is installed again. A config file in `~/.config/dfr/` can change the location, because `~/.config` is the standard place for config files.
- **Folder name**: the ID only. Then `rename` does not move the folder.
- **ID**: 3 random characters that grow to 4, 5 and so on when all IDs of a length are used. Short IDs are easy to type and read. `mkdir` fails on an existing folder, so two sessions cannot get the same ID.
- **Data**: `.thing.json` and `.log.jsonl` in the folder of the thing. All data of a thing stays in one folder, and no database can disagree with the files.
- **Log**: one line for each command, also for commands that change nothing. Then the log shows which sessions read the thing.
- **Frontmatter**: optional. A required field adds work for each write and gives little value.
- **Session**: from `CLAUDE_CODE_SESSION_ID`. Claude Code sets this variable in each Bash call, so no hook is necessary. This was checked in a Claude Code session.
- **File order**: a list in `.thing.json`. Number prefixes in filenames would change the names on each reorder.
- **Reorder**: `files:reorder` takes filenames in the new order, and the other files keep their old order after them. Then a session can move one file to the top without a list of all files.
- **Archive**: move to `.archive/`, with a macOS style number on a name clash. No archived file is overwritten.

## Open

- `list`, `search` and `init` without a thing have no `.log.jsonl` to write to. It is not decided if these commands are logged.
- `.thing.json` gets many writes from many sessions. Phase 2 must lock the file for each write, or two sessions can lose each other's changes.
- To find a free ID gets slow when nearly all IDs of one length are used, because random tries hit used IDs. This is a problem only near 29,791 things.
